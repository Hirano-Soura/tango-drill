# バージョン

アプリのバージョンは `n.m.l` の 3 区域で管理する(Minecraft と同じ並び)。
進捗はここに書かない。[50_Tasks.md](50_Tasks.md) を見る(UD-3)。

## 1. 規則

| 区域 | 名前 | 上げる場面 |
| --- | --- | --- |
| `n` | major | 授業での公開など、利用者への区切りとなる版。**最初の公開版を `1.0.0` とする**。互換を壊す変更(保存形式を読めなくする等)も上げる。INV-3 により、バックアップと取り込み形式の過去の版は読み続けるので、通常は上がらない |
| `m` | minor | 利用者に見える機能・仕様の追加(コミットの種類が `feat`) |
| `l` | patch | 不具合の修正・文書・手順・素材・開発用の道具の変更(`fix` `docs` `chore` など) |

- `n` が 0 の間は**公開前の pre-release**。今の版もこれに当たる。`m` と `l` は上げると 0 に戻す(`0.5.1` の次の機能追加は `0.6.0`)
- 版の書き方は数字だけの `n.m.l`(`-pre` などの接尾辞は付けない)。git のタグは先頭に `v` を付けて `v0.16.2` とする
- **取り込み形式・バックアップ形式の版(`tango-drill-backup/v1` など。INV-3)とは別物**。アプリのバージョンが上がっても、それらの版は形式を変えたときだけ上がる
- 上げる単位は、`main` に統合する 1 回(PR)ごとに 1 回。`feat` を 1 つでも含めば minor、無ければ patch
- 上げるときに同じ変更で更新する場所は 3 つ: `core/version.js` の `VERSION`、`package.json`(と `package-lock.json` の先頭 2 か所)の `version`、下の履歴の表の先頭に足す行。3 つの一致は `tests/core/version.test.js` が検査する
- 版を付けたコミットに、注釈付きのタグ `vn.m.l` を付ける
- 画面では設定タブの「データについて」に今の版が出る

## 2. 履歴
