# 通知

利用者に知らせるべきアプリの変更を、通知タブに載せる規則。重要なお知らせは、読むまで通知タブのボタンの右上に赤い点を出す。

| 実装 | 役割 |
| --- | --- |
| `core/notices.js` | お知らせの一覧 `NOTICES`(新しい順)と、未読の判定(`unreadImportant` / `unreadIds`) |
| `app/tabs/notice.js` | 通知タブ。お知らせを並べ、「重要」「新着」の印と、お知らせに付いた操作を出す |
| `app/main.js` | タブのボタンの赤い点と、通知タブを開いたときの既読(`readNotices`) |
| `app/storage.js` | 読んだお知らせの id を、端末ごとの設定 `noticesSeen` に置く([22_Storage.md](22_Storage.md) §4) |

進捗はここに書かない。[50_Tasks.md](50_Tasks.md) を見る(UD-3)。

## 1. 載せるもの

| 項目 | 規則 |
| --- | --- |
| 載せる変更 | 利用者に見える変更のうち、知らないと困るか、知ると使い方が変わるもの。版(`m` が上がる変更。[53_Versions.md](53_Versions.md) §1)ごとに考え、全部を載せる必要はない |
| 重要(`important`) | **利用者が自分で何かをしないと、変更の効き目が得られないもの**(例: 既存の語に自他を補う)と、今までの使い方が変わるもの。重要なものだけが赤い点を出す |
| `id` | 既読の記録の鍵。**載せたあとは変えない**(変えると、読んだ人にもまた点が出る)。`YYYY-MM-DD-<短い名前>` の形にする |
| `version` / `date` | 載せた版と日付。新しい順に並べる。今の版(`core/version.js`)より新しい版は名乗らない |
| 本文(`body`) | 段落の配列。アプリの中の固定の文なので、画面は `esc` を通さずに HTML として入れる(Q&A と同じ)。利用者の入力を混ぜない |
| 操作(`action`) | 本文の下に出すボタン。今は `trans`(自他の無い動詞に自他を補う依頼文を作る。[20_ImportFormat.md](20_ImportFormat.md) §6)だけ |

- お知らせは消さない(古いものも、変更の経緯として読めるように残す)。数が増えて読みにくくなったら、そのときに畳み方を決める
- 本文はアプリの今の動きを書く。書いた動きを後で変えたら、お知らせを書き換えずに新しいお知らせを足す(Q&A は今の動きに合わせて直す。[23_Screens.md](23_Screens.md) §5)

## 2. 赤い点と既読

- **読んでいない重要なお知らせが 1 つでもあれば、通知タブのボタンの右上に赤い点を出す。** タブの名前(「通知」)は変えず、点は読み上げ用の説明(`aria-describedby`)で知らせる
- 通知タブを開いたときに、まだ読んでいないお知らせを(重要でないものも)すべて既読にする。点はすぐ消える
- 開いたときに読んでいなかったお知らせには「新着」を付ける。別のタブへ移ってから開き直すと消える
- 既読は端末のブラウザごとの設定に置き、バックアップには入れない。別の端末・別のブラウザで開くと、もう一度点が出る
- 既読を保存できなかったとき(保存層の失敗)は、そのまま続ける。次に開いたときにまた点が出て、読み直せば消える
- 初めて開いた利用者(単語帳が空)にも、それまでの重要なお知らせの点を出す(仮)。変更の説明が新しい機能の案内も兼ねるため

## 3. 確かめ方

| 対象 | 手段 |
| --- | --- |
| お知らせの id の重なり・日付と版の形・並び・今の版より新しい版を名乗らない・点の判定 | `tests/core/notices.test.js` |
| 既読の保存(文字列の配列だけを読む) | `tests/app/storage.test.js` |
| 画面: 点が出る・タブを開くと消え、開き直しても出ない・「新着」と「重要」・スマホ幅ではみ出さない | `npm run e2e` の `tests/e2e/trans.spec.js`(陽性対照は [23_Screens.md](23_Screens.md) §6) |
| 載せるべき変更を載せたか・重要の判断 | 目視(版を上げるときに §1 の表で見る) |
