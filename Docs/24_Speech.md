# 読み上げ

学習の画面で、見出し語と例文を英語の音声で読み上げる。ブラウザの音声合成(Web Speech API の `speechSynthesis`)を使い、
音声のファイルもサーバーも持たない。どの声で読めるかは端末とブラウザで変わるので、その違い(§2)を前提に規則(§4)を決める。

| 実装 | 役割 |
| --- | --- |
| `core/speech.js` | 使ってよい音声の選び方(`englishVoices` `pickVoice`)と、見出し語から読む文の作り方(`speechText`)。ブラウザの API には触れない(INV-6) |
| `app/speech.js` | ブラウザの音声合成を呼ぶ唯一のファイル(`speak` `stop` `voices`)。`doc_audit.py` の INV-1 がほかのファイルでの呼び出しを FAIL にする |
| `app/tabs/study.js` | 学習の画面の「発音」「例文を聞く」と自動読み上げ |
| `app/tabs/settings.js` | 設定タブの「読み上げ」の欄(自動読み上げ・音声・速さ・試し聞き) |
| `tests/core/speech.test.js` | §4 の音声の選び方と読む文。INV-1 の陽性対照つき |
| `tests/e2e/speech.spec.js` | 画面の確認。音声合成を偽物に差し替え、読ませた文と声を記録して見る(§5) |

進捗はここに書かない。[50_Tasks.md](50_Tasks.md) を見る(UD-3)。

## 1. 方針

- **端末の中にある音声(`localService` が `true` の音声)だけで読む。** インターネット経由の音声は、読む文(単語・例文)を
  音声を作るサーバーへ送る。単語を外部へ送らない約束(INV-1)に当たるので使わない
- 使える英語の音声が無い端末では読まない。言語(`lang`)だけを指定して読ませることもしない
  (声を指定しないと、ブラウザがインターネット経由の音声を選ぶことがあるため)
- 読み上げは学習を助ける付け足しであり、無くても学習はできる。読めない端末では、理由を設定タブに出す

## 2. ブラウザと OS ごとの違い

`speechSynthesis.getVoices()` が返す一覧は、OS が持つ音声と、ブラウザが独自に足す音声の合計になる。
各音声の `localService` が、端末内(`true`)かインターネット経由(`false`)かを示す。

| 端末 | ブラウザ | 端末内の英語の音声(使う) | インターネット経由の音声(使わない) | 注意 |
| --- | --- | --- | --- | --- |
| Windows | Chrome | OS の音声(Microsoft David・Zira・Mark など) | `Google US English` `Google UK English Female` など | Google の音声は 14 秒ほどを超える読み上げで止まる不具合がある(単語・例文の長さではほぼ当たらない) |
| Windows | Edge | OS の音声(Chrome と同じ) | `Microsoft Aria Online (Natural)` のような名前の声が多数(言語も地域も多く、自然な声) | Edge の Natural の声は最も自然だが、すべてインターネット経由 |
| Windows | Firefox | OS の音声だけ | 無し | — |
| macOS | Safari | OS の音声(Samantha・Daniel など) | 無し | OS の設定で後から入れた高品質版は一覧に出ないことがある |
| macOS | Chrome / Edge | OS の音声 | Windows と同じく Google / Online の音声 | — |
| iPhone / iPad | Safari(ほかのブラウザも中身は Safari と同じ) | OS の音声(Samantha など) | 無し | 後から入れた高品質版が一覧に出ないことがある。どの音声も「既定」と名乗る(`default` が当てにならない) |
| Android | Chrome | 端末の音声読み上げエンジン(Google の音声サービスなど)の言語と地域 | — | 一覧は声ではなく言語・地域の並び。言語の書き方が `en_US` のように下線区切り |
| Android | Firefox | — | — | 音声合成を持たない。読み上げのボタンを出さない |
| Linux | Chrome | 入れてあれば eSpeak など | Google の音声 | 音声エンジンを入れていないと、端末内の音声が 0 になる(開発に使うクラウドのコンテナはこれに当たり、一覧が空だった) |

- **英語は、どの主要な OS も端末内の音声を持つ。** そのため、インターネット経由の音声を使わなくても、PC でもスマホでも読める見込みが高い。
  ただし Windows の端末内の音声(David・Zira)は、Edge の Natural の声より機械的に聞こえる
- 日本語版の Windows に英語(米国)の音声が入っているかは端末による(**未検証**)。入っていなければ、Windows の設定の「時刻と言語」→「音声認識」から英語の音声を足す。
  足した音声がブラウザの一覧に出るか(ブラウザの再起動が要るか)も未検証
- 速さ(`rate`)の効き方は音声エンジンごとに違う。同じ「ふつう」でも端末によって速さが少し違う

出典(2026-10-07 に確認): readium の [Web Speech の比較](https://github.com/readium/speech/blob/main/docs/WebSpeech.md)
(ブラウザごとの音声の数・Chrome の 14 秒の不具合・Android の言語の書き方・Safari の高品質版・Android の Firefox)、
MDN の [`SpeechSynthesisVoice.localService`](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)、
Microsoft Edge の [クラウドの音声の告知](https://blogs.windows.com/msedgedev/2019/08/14/cloud-powered-voices-microsoft-edge-chromium/)。

### ドイツ語ドリルとの違い

学習ポータルのドイツ語ドリル(`german-drill`)は、PC では Edge で開くよう案内している。理由は §2 の表から読める。

- 日本語版の Windows は、ふつうドイツ語の音声を持たない。端末内の音声が無いので、Chrome ではインターネット経由の `Google Deutsch` か、
  ドイツ語ではない声で読むことになる。Edge ならドイツ語の Natural の声(インターネット経由)が使える
- スマホ(iOS・Android)は OS の音声読み上げがドイツ語の声を持つので、端末内の音声で自然に読める。スマホで問題なく聞こえるのはこのため
- ドイツ語ドリルはインターネット経由の声も選ぶ。このアプリは INV-1 があるので選ばない。英語は端末内の音声がどの OS にもあるので、この違いが表に出にくい

## 3. 画面

| 場所 | 中身 |
| --- | --- |
| 学習(2 段階クイズ・カード) | 見出し語の横の「発音」で見出し語を読む。答えたあと(カードは裏を見せたあと)は「例文を聞く」で例文を読む |
| 学習(自動読み上げ) | 設定で入れると、問題を出したときに見出し語を 1 度だけ読む。答えたあと・中断から再開したときの描き直しでは読み直さない。カードで前へ戻ると、戻った問題をまた読む。既定は切(授業中に音が出ないように) |
| 設定「読み上げ」 | 自動読み上げ・音声(自動 / 使える音声の一覧)・速さ(ゆっくり / ふつう / はやい)・試し聞き。インターネット経由の英語の音声があれば、その数と使わない理由を添える |

- 読み上げを持たないブラウザでは、学習の画面にボタンを出さず、設定タブにそう出す
- 使える英語の音声が無いときは、ボタンを押せなくし、設定タブに理由(と、インターネット経由の音声の数)を出す
- 音声の一覧はページを開いたあとに届くことがある。届いたら学習タブと設定タブを描き直す
- タブを移る・中断する・やめるときは、読んでいる途中でも止める
- 設定(自動読み上げ・音声・速さ)は端末ごとで、バックアップには入れない([22_Storage.md](22_Storage.md) §2 の単語帳の形は変えない)

## 4. 規則

### 音声の選び方(`pickVoice`)

1. 一覧から、`localService` が `true` で、言語が英語(`en` か `en-` で始まる。`en_US` のような下線区切りも英語とする)の音声だけを残す
2. 並べる順: 地域が 米国 → 英国 → カナダ → オーストラリア → ニュージーランド → アイルランド → そのほか(TOEIC の音声に合わせて米国を先にする)。
   同じ地域の中では、名前に Enhanced・Premium などを含む端末内の高品質版を先にする。それ以外は一覧の順を保つ
3. 設定で音声を選んであり、それが 1 の中にあれば使う。無ければ(別の端末・音声を消した・インターネット経由の音声を指していた)2 の先頭を使う
4. 1 が空なら読まない

### 読む文(`speechText`)

例文はそのまま読む。見出し語は、句表現の目印をそのまま読むと「エー」「チルダ」「マイナス」になるので、次のように直してから読む。

| 目印 | 扱い | 例 |
| --- | --- | --- |
| `A` `B`(2 語目以降の 1 文字の大文字、`A's` を含む) | 読まない | `be aware of A` → `be aware of` |
| `-ing` `~ing` | `doing` | `prevent A from -ing` → `prevent from doing` |
| `~` `〜` `…` | 読まない | — |
| `sb` `sth` | `somebody` `something` | `take care of sb` → `take care of somebody` |
| 括弧 | 括弧だけを外す | `(be) eligible for` → `be eligible for` |
| ` / ` で並んだ言い換え | 最初だけを読む | `on behalf of A / on A's behalf` → `on behalf of` |

- 先頭の `A` は冠詞などかもしれないので残す(`A lot of`)

| 実際の声で読めること・聞き取りやすさ | 実機(下の手順)。偽物の音声合成では見られない |

### 実機での確認の手順

端末ごとに次を見る。結果は [50_Tasks.md](50_Tasks.md) の該当タスクに書く。

1. 設定タブの「読み上げ」を開き、音声の一覧に何が出るか、インターネット経由の音声の数の注記が出るかを見る
2. 「試し聞き」で読まれるか、声が英語として自然に聞こえるかを聞く
3. 学習タブで句表現(`A` などを含む語)の「発音」を押し、目印を読まないことを聞く
4. 自動読み上げを入れて数問解き、1 問に 1 度だけ読まれることを聞く(iPhone では、最初の 1 回がボタンを押したときでないと鳴らないことがある)

見る端末: Windows の Chrome と Edge(desktop・laptop)、iPhone の Safari、Android の Chrome。
