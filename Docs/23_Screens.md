# 画面

5 つのタブの役割と、画面での操作の規則。形式・出題(2 段階クイズの判定を含む)・保存の規則そのものは
[20_ImportFormat.md](20_ImportFormat.md)・[21_Quiz.md](21_Quiz.md)・[22_Storage.md](22_Storage.md) にあり、ここでは画面がそれをどう使うかだけを書く。
追加・編集・削除の規則(§3)は画面の操作として定義し、実装は `core/book.js` に置く(Node で検査するため)。

| 実装 | 役割 |
| --- | --- |
| `index.html` | 画面の枠と見た目(明暗の配色・スマホ幅) |
| `app/main.js` | 保存層を開き、タブを切り替える。単語帳を変える操作をまとめる(`commit`)・「元に戻す」 |
| `app/dom.js` | エスケープ・日付・ファイルの書き出し・各タブが受け取る文脈(`Ctx`) |
| `app/wordForm.js` | 1 語の入力欄(追加と編集で共用) |
| `app/tabs/*.js` | 各タブ |
| `tests/e2e/flow.spec.js` | Playwright による通し確認(§6) |

進捗はここに書かない。[50_Tasks.md](50_Tasks.md) を見る(UD-3)。

## 1. タブ

| タブ | 中身 |
| --- | --- |
| 学習 | 復習ミックス(または全語をシャッフル)を、2 段階クイズかカードで解く |
| 単語帳 | 一覧・絞り込み・印・編集・削除 |
| 追加 | 1 語ずつ手で足す(貼り付けの取り込みは T-5.1 でここに足す) |
| 記録 | 語ごとの正誤・思い違いの集計、並べ替え、CSV の保存 |
| 設定 | 誤答に内蔵語彙を使うか(端末ごと。バックアップには入れない)。バックアップの画面は T-5.2 でここに足す |

- 単語帳が空なら追加タブから、語があれば学習タブから始まる

## 2. 単語帳を変える操作と「元に戻す」

- 単語帳を変える操作は、すべて `commit` を通して保存してから描き直す(画面の状態と保存した中身をずらさない)
- **「元に戻す」は、直前の追加・編集・削除の 1 回だけを取り消す。** 画面の下に出し、次に単語帳を変える操作
  (回答の記録・印を含む)をするか、タブを移ると消える。取り消すと、その操作の直前の単語帳を保存し直す
- バックアップからの復元の「元に戻す」は別のもの([22_Storage.md](22_Storage.md) §3。次の復元まで残る)

## 3. 追加・編集・削除

| 操作 | 規則 | 実装 |
| --- | --- | --- |
| 追加 | 取り込みと同じ読み手と確認表を通す(品詞の別名の正規化・INV-4 の重複判定)。**手で入れた 1 語は入力欄そのものが確認に当たる**ので、確認表の行が「足す」のときだけ確定して保存する。既にある語に当たるときは足さずに、単語帳からの編集へ案内する。例文があれば出どころは自作 | `addOneWord` |
| 編集 | 取り込みと同じ読み手で正規化する。**例文を消すと和訳と出どころも消える。** 例文を書き換えると出どころは自作になる。見出し語か品詞を変えて鍵が変わるときは追加日・記録・印も移す。既にある語と同じ鍵には変えられない(INV-4) | `editWord` |
| 削除 | 語・追加日・印を消し、記録は残す(同じ鍵の語を足し直すと記録がまた付く) | `deleteWord` |

## 4. 学習

- 2 段階クイズの判定と記録の表は [21_Quiz.md](21_Quiz.md) §6(`stage1Record` / `stage2Judge`)。画面は判定を表示して記録するだけ
- **1 問で記録はちょうど 1 件**なので、2 段階クイズでは前の問題へ戻れない(戻って解き直すと記録が二重になる)
- 結果は「正答数 / 記録した問題の数」。カードで出した問題と途中で飛ばした語は分母に入れない
- 選択肢は問題ごとに 1 度だけ作る(`buildChoices`。描き直しても並びが変わらない)
- 4 択を作れない問題(意味が無い・語が 4 語未満で内蔵語彙を使わない設定・誤答が揃わない)はカードで出し、記録しない。理由を画面に出す
- カード形式は記録しない。前の問題へ戻れる
- 解いている途中で単語帳から消した語は飛ばす(INV-5: 単語帳に無い語は出さない)。見出し語か品詞を変えて鍵が変わった語も、消した語と同じに飛ばす。
  意味などを編集した語は、問題文は新しい内容で出し、選択肢は問題を出した時点のものを使う
- 復習ミックスの見出しは、基準の回が今日なら「今日」、違えば「直近(日付)」

## 5. 表示の規則

- **利用者の入力は必ず `esc` を通してから HTML に入れる**(§6 の確認で、タグを入れても要素にならないことを見る)
- 入力欄には必ず名前を付ける。見えるラベルは `for` で結び(ラベルで囲むと入力中の文までラベルの名前に含まれる。
  [52_Pitfalls.md](52_Pitfalls.md) P-7)、見えるラベルの無い欄(絞り込み・学習の条件の選択)は `aria-label` を付ける
- 記録タブの「回答数」は今の単語帳の語の分だけを数える(消した語の記録は数えない)。
  バックアップの確認に出す「記録件数」(`countBook`)は消した語の分も数える([22_Storage.md](22_Storage.md) §3)
- スマホ幅(390px)で横にはみ出さない。単語帳は表ではなく 1 語 1 枚の並びにする
- 記録の CSV には、Excel で文字化けしないよう BOM を付けて保存させる(`statsCsv` は付けない。[21_Quiz.md](21_Quiz.md) §6)
- 送信はしない。ファイルの保存は端末内で作ってダウンロードさせる(INV-1)

## 6. 確かめ方

| 対象 | 手段 |
| --- | --- |
| 追加・編集・削除の規則 | `tests/core/book.test.js` |
| 2 段階クイズの判定表・1 問 1 件([21_Quiz.md](21_Quiz.md) §6) | `tests/core/review.test.js` |
| 設定の保存 | `tests/app/storage.test.js` |
| 画面の通し(追加 → 学習 → 記録 → 編集 → 削除 → 元に戻す)・「わからない」のあとは記録しない・4 択を作れない問題のカード・重複の追加・入力のエスケープ・スマホ幅ではみ出さない | `npm run e2e`(Playwright。PC 幅とスマホ幅の 2 通り。はみ出しはスマホ幅だけで、各タブの最初の画面・クイズの 2 段階と判定のあと・記録の表・編集欄を見る。レポートは `Temp/tango-drill_e2e.json`。`--reporter` を指定して回すとレポートが書かれないので、記録に残す実行は `npm run e2e` で行う) |
| 「元に戻す」が消える条件(回答・印・タブの移動) | 目視(`app/main.js` の `commit` と `go`) |

- ブラウザはその端末の Edge を使う(ブラウザのダウンロードは要らない)。別のブラウザを使うときは `PW_CHANNEL` を設定する。
  Edge が見つかるかは起動確認(`check_env.py`)が見る
- 画面の確認は三本立ての外で、節目に回す(CLAUDE.md §1)。GitHub Actions では回さない
