(同じ規則は `app/tabs/qa.js` の答えにもある)。

## student_intro.html

### 経緯

2026-09-30、授業で受講者に口頭で紹介した。そのあとに文字で送る補足として、本人の依頼で作った。依頼の内容は次のとおり。

- 形式はリッチテキストか HTML。HTML にした(ブラウザで開いて全体をコピーし、Google Classroom・Teams・メールなどに貼れば書式つきで送れる)
- 構成は「注意点(最初に必ず読む場所)」「基本的な使い方」「今後のアップデート」など
- 注意点に入れるもの: 口頭で伝え忘れた「ホーム画面への追加」、「キャッシュの削除は大丈夫か」への答え、
  動作を確かめていないが不利になりうるブラウザ
- 同じ日に本人の指示で、注意点を想定問答(Q1〜Q5)の形に書き直した。授業中に受講者から質問は出ていないので、
  どの問いも実際に出た質問としては書かない(ホーム画面への追加を伝え忘れたことだけは事実として書く)

### 確かめていない前提(ブラウザの一般的な仕様に拠る)

次の記述はこのアプリで確かめたものではなく、ブラウザの一般的な仕様に拠る。実機で確かめたら、この表と案内文を直す。

| 記述 | 確かめ方 |
| --- | --- |
| iPhone の Safari は、しばらく開いていないサイトの保存データを消す(目安 7 日)。ホーム画面から開くと影響を受けにくい | T-7 で実機に載せるときに、長く開かない期間を置いて単語帳が残るかを見る |
| iPhone では、ホーム画面から開いたアプリは Safari とは別の単語帳になることがある。アイコンを削除すると単語帳も消えることがある | iPhone の実機で、Safari で 1 語足してからホーム画面に追加して開き、単語帳が空かを見る |
| Chrome の「キャッシュされた画像とファイル」だけの削除では消えず、「Cookie とサイトデータ」で消える | Chrome で 1 語足してから各項目で削除し、単語帳が残るかを見る |
| LINE などのアプリ内ブラウザでは、データが消えやすい・ファイルを保存できないことがある | LINE でリンクを開いて 1 語足し、閉じて開き直す・「書き出す」を押す |
